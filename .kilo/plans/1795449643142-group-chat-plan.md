# Group Chat Plan

## Summary
Add group conversations as `kind = 'group'`, reusing messages/members/realtime. Backend migrations/RPCs/RLS are required first and must be added to `NEEDS_API.md` (no direct edits to migrations/types/api per project rules). UI work stays in `src/features/chat/**` and chat pages.

## Backend requests (record in NEEDS_API.md)
- Expand `conversations.kind` CHECK to allow `'group'`; add `title text`, `created_by uuid`.
- Add `conversation_members.role` (admin/member) and `removed_at timestamptz`.
- Indexes: active membership lookups and message pagination.
- RLS via `is_active_conversation_member()` helper; active members read/send, removed lose all access immediately.
- RPCs (SECURITY DEFINER, rate-limited): `createGroup`, `addGroupMembers`, `removeGroupMember`, `renameGroup`, `leaveGroup`, `deleteGroup`, `listGroupMembers`.
- Rules: trim title 1-80 chars; dedupe usernames; enforce 20-member cap (creator + up to 19 invitees) atomically; creator cannot leave unless delete/transfer; delete is hard delete.

## UI (chat scope only)
- `ChatListPage`: group title + active member count; "New group" entry point.
- New `NewGroupPage`: title input + username chips (max 19) + create.
- `ChatPage`: header title + "N members"; otherUser null for groups.
- `Avatar` group initials; keep MessageStatus unchanged for own messages.
- No system messages; membership changes update metadata only.

## Data mapping
- direct: `otherUser` present, title fallback, memberCount 2.
- group: `otherUser` null, title from conversation, memberCount active members.

## Validation
- Unit: MessageStatus (done), GroupHeader, parseGroupMembers.
- Integration: create/send/receive, max cap, creator-only remove/delete, non-member and left user access, realtime to 2+ members.
- Manual: mobile, 44px targets, dark/light.

## Decisions
- Titles not unique.
- Max 20 members (creator + 19).
- Only creator removes/deletes; others leave.
- Creator cannot leave unless delete.
- Removed/left lose all access immediately.
- No system messages.

## Open questions
- Rate limits (10 groups/day) backend confirmation.
- Realtime subscription routing verification.
