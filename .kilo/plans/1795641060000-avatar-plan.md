# Avatar Selection Page Plan

## Goal
Add an avatar gallery page where users pick a visual avatar from many preset options (instead of typing a seed name), accessible from Settings. Selection persists via the existing `updateAvatarSeed(seed)` RPC.

## Decisions
- **Avatar source:** preset seed strings rendered through the existing `IdenticonAvatar` component. No image assets added, no contract files edited (`types/database.ts`, `src/lib/api.ts` are contract-locked).
- **Page (not inline):** new route `/settings/avatar` → `AvatarPage` component, linked from SettingsPage's avatar section. Matches "add an avatar page ... accessed in user settings."
- **Gallery size:** 24 preset avatars (4 columns × 6 rows), each a distinct seed + label.
- **Selection flow:** click an avatar card to select (highlight border), then press an explicit "Save" button that calls `updateAvatarSeed(selectedSeed)`. Include a "Default" option that clears to the username-based identicon.
- **SettingsPage edit:** replace the avatar text input (`<input value={avatarSeed} ...>` + Save) with current-avatar preview + a "Change avatar" link navigating to `/settings/avatar`. Keep `updateAvatarSeed` import usage in AvatarPage only.

## Files
- `src/lib/avatarPresets.ts` (new) — `AVATAR_PRESETS: Array<{ id: string; label: string; seed: string }>` (24 entries) + helper `getAvatarPreset(id?)`.
- `src/features/settings/AvatarPage.tsx` (new) — page with header, back link to `/settings`, 24-card grid, selection highlight, Save button, status messages (saved/error), uses `updateAvatarSeed` from `@/lib/apiClient`.
- `src/features/settings/SettingsPage.tsx` (edit) — avatar section: show current `IdenticonAvatar` + "Change avatar" `<Link to="/settings/avatar">`; remove text input and inline Save.
- `src/App.tsx` (edit) — add protected route `path="/settings/avatar"` → `AvatarPage`.

## Data flow
1. User opens Settings → clicks "Change avatar" → navigates to `/settings/avatar`.
2. `AvatarPage` mounts, calls `getCurrentUser()` to read current `avatarSeed`, highlights matching preset.
3. User clicks a card → sets `selectedId` state (highlight border).
4. User clicks Save → `updateAvatarSeed(selectedSeed ?? username)` → on success show "Saved", re-fetch current user to refresh preview; on error show message.
5. SettingsPage re-renders with new avatar preview on return/navigate back.

## Boundaries (contract files untouched)
Do NOT edit: `supabase/migrations/*`, `src/types/*`, `src/lib/api.ts`, `src/lib/apiClient.ts`, `.env.example`. `updateAvatarSeed` already exists in `src/lib/api.ts:998` and `src/lib/apiClient.ts` re-exports it.

## Failure modes
- `getCurrentUser` fails → show error state, disable Save.
- `updateAvatarSeed` errors → show error message, keep selection, allow retry.
- No preset matches current seed → highlight "Default" or none; Save with default clears to username.
- `localStorage` not used.

## Validation
- `npm run typecheck` — passes
- `npm run lint` — passes (0 warnings)
- `npm run test` — existing tests still pass
- Manual:
  1. Settings → click "Change avatar" → `/settings/avatar` loads 24-card grid.
  2. Click an avatar → card highlights; previously selected un-highlights.
  3. Click Save → "Saved"; SettingsPage avatar preview updates to new identicon.
  4. Click "Default" → Save → avatar reverts to username-based identicon.
  5. Navigate back to Settings → preview persists.

## Open questions / out of scope
- Custom image upload (would require contract change to store image URL + backend storage) — explicitly out of scope.
- Per-conversation or group avatar — out of scope (group avatar already via group title/identicon).
